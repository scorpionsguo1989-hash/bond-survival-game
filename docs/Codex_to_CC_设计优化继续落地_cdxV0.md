## 本轮目标

请直接落地 UI 优化，优先级如下：

### P0：保留并落地 Round 1 命运卡改动

- 开局页要一次展示“三大挑战”，不要让玩家必须滚动/展开才看到。
- slogan 使用 `命运由你改写`，不要再用 `你的命运已定`。
- `01 / 02 / 03` 下方红色竖线不要贴错位置，应作为单独视觉 rail 对齐每行文本。
- 移动端任务简报必须能自然下滑看全，避免卡片内部截断。

### P0：落地 Round 2 主界面结构

桌面端：

- 三栏结构保持金融终端风格。
- 左栏是角色状态：
  - CFO/GOV：`我的指标` -> `本局目标`
  - IM：`我的指标` -> `赎回压力` -> `本局目标`
- 中栏是主决策流：
  - 事件卡
  - B/C/D 事件选项
  - 最近 LOG
  - 主动操作 A1-A5
  - 季末预演
  - 决策日志
- 右栏只放角色图表与市场脉冲，不再放目标卡。
- 减少大面积空白，主动操作必须出现在事件下方，不要挤在左栏底部。

移动端：

- 不要简单把所有内容无限上下堆叠。
- 使用分段页签/横向切换思路组织：
  - `事件 / 操作`
  - `指标 / 日志`
  - `目标 / 风险`
- 移动端仍要能整页自然滚动，文字不能重叠或被底部遮挡。

### P0：补 Round 3 弹层组件

请实现三类组件，替代原生浏览器交互：

1. 操作输入 Modal，替代 `prompt()`
   - 触发场景：例如点击 `申请银行续贷`，输入 0.5-5 亿金额。
   - 标题：操作名。
   - 描述：操作说明。
   - 数字输入：label `借款金额（亿）`，有 min/max 提示。
   - 可加 slider 选择金额。
   - `预计影响` 信息块：展示 cash +X / creditUsed -Y 等 effects。
   - 按钮：取消 / 确认。
   - 风格要像严肃的金融终端交易确认，不要像普通 SaaS 表单。

2. Toast，替代 `alert()`
   - success：绿色边框/勾号，用于操作成功。
   - error：红色边框/叉号，用于失败或校验错误。
   - info：青蓝边框/i，用于自动保存、排名提交等。
   - 桌面右上浮出，移动端顶部下拉。
   - 3 秒自动消失，可手动关闭。
   - 支持一行/两行文案。

3. 危机 Modal
   - 触发示例：
     - CFO cash < 0.5 亿
     - IM 赎回压力 >= 80
     - GOV 隐债敞口 > 200 亿
   - 全屏半透明深红遮罩。
   - 顶部红色 banner：`危机警报 · 时间暂停 · 必须处置后继续`
   - 主卡片包含标题、描述、三个关键指标。
   - 三个处置选项，每个包含 label、代价标签、desc、effects 预告。
   - 选项卡片要有“慎重选择”的分量感，不要只是普通按钮。

## 视觉约束

- 保留暗色金融终端美学，不要改成浅色 SaaS。
- 继续使用 CFO 青蓝 / IM 金黄 / GOV 朱红的角色色。
- 提升字号和层级，但保持高信息密度。
- 不要做过度动画、卡通图标、营销式大 hero。
- 卡片圆角克制，终端感优先。
